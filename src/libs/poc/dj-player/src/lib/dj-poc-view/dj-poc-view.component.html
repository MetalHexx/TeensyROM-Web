Cues store machine state, not a position, so a hop restores in constant time instead of re-emulating from init — no main-thread stall, and the frame clock keeps ticking through it. A snapshot only means anything to the machine it came from, so anything that re-inits one — loading a tune, stopping, changing subtune — clears all four slots.

A hop rides the frame clock rather than sending beside it: the cartridge counts every SID-data packet as a frame and drains exactly one per timer tick, so anything injected between ticks is a frame it never drains and the queue grows until it overflows and resets. Two packets go out on the next two ticks — gate-off, then the resync — so the rate stays at one packet per frame no matter how hard the cue buttons are hit, at the cost of up to ~40 ms of latency per hop. A hop arriving while one is still pending replaces it, so spamming never builds a backlog.

Jitter is the spread of the gap between audio callbacks, measured on the callback rather than on emitted frames so it reads the same whatever multispeed the tune carries. Mean interval and drift can both look healthy while individual callbacks scatter, and scatter is what empties the cartridge's queue — no callback means no packet, and a queue that runs dry re-buffers. The worst gap is the number that catches a rare dropout: a single long main-thread stall barely moves σ but empties any buffer outright. Worst gap is a running maximum that never decays, so the late count beside it separates one spike from a recurring one.

Drift is the check on the clock itself. Frames fall due against measured elapsed time rather than the buffer duration the sample rate implies, so a healthy stream holds drift near zero. A figure that climbs steadily means we are emitting at a different rate from the one the recipe advertises to the cartridge — which drains its queue faster than we fill it and leaves the firmware's slow re-timer hunting, the swing you can watch on the C64's bar graph.

The host cannot read the cartridge's queue fill — watch the C64's own screen too: the buffer-fill bar graph, per-SID write spinners, the 25 register lights, the packet-error indicator, and the read-error indicator.
